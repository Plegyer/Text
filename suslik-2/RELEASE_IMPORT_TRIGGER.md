# SUSLIK 2 — автоматика импорта полной игры из ZIP (15.10.2026)

**Подготовлено и проверено на GitHub:** отдельная служебная ветка `suslik-2/import-recovery-staging-20261015`, файл `.github/workflows/suslik2-import-release.yml`, запуск GitHub Actions (проверка черновика релиза). Ветка `main` неизменна.

## Единственный необходимый внешний перенос байтов

Пользовательский оригинальный ZIP `SUSLIK2-CANONICAL-Windows-2026-10-15.zip` (≈117 МБ, 103 файла, SHA-256 `f863a06e08118460d5fdca57653430bdd277929969cd436a95f4885621621c8c`) сейчас находится как прикреплённый к чату артефакт. GitHub API-коннектор не принимает файл из локального контейнера, а контейнер не имеет исходящего DNS. Автоматизировать перемещение **байтов** между этими изолированными средами напрямую нельзя.

GitHub Actions создал черновик релиза в `https://github.com/Plegyer/Text/releases`, tag `suslik2-canonical-20261015`. От автора нужен **один перенос ZIP**: открыть черновик, добавить ровно `SUSLIK2-CANONICAL-Windows-2026-10-15.zip` в **Assets** и нажать «Publish release». Не извлекать ZIP, не переписывать код, не собирать архив заново.

**После этого** нужно повторно вызвать workflow `Publish complete SUSLIK 2 portable source` на служебной ветке. Следующий чат с GitHub-доступом может просто обновить этот файл (добавить строку с датой/временем) через `update_file`: workflow автоматически запустится по `push`. Либо владелец GitHub может выбрать «Re-run all jobs» для предыдущего запуска в `https://github.com/Plegyer/Text/actions`.

Workflow выполняет:
1. Загружает **именно указанный asset** с tag `suslik2-canonical-20261015`.
2. Строго сверяет SHA-256 исходного ZIP и безопасно проверяет 103 файла.
3. Сверяет `FILES_SHA256.txt` и наличие четырёх оригинальных PNG и MP3 фермы, файлов игрового хоста.
4. Запускает **85 автотестов** на Node.js.
5. Только если всё прошло, создаёт новую единую ветку `suslik-2/portable-canonical-20261015` и публикует полный `suslik-2/` с медиа. `main` и старый проект не меняются.

**Не считать этап завершённым до появления этой ветки** и последующей проверки `gameplay-ui.js`, четырёх PNG и MP3 через GitHub. После подтверждения статус надо обновить на канонической ветке и можно работать там в любом новом чате с правами записи.

## Текущее состояние

Автоматический workflow присутствует в GitHub и **подтверждён реальным запуском**. Черновик релиза создан, но ZIP пока **не загружен**, поэтому сама каноническая ветка ещё не опубликована. Это операционный блокер, не отсутствие готового проекта.
