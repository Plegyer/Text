# SUSLIK 2 — Ночная «Тренировка» после квеста бригадира

**Статус:** авторская механика утверждена, изолированные модули + host hooks готовы. **Реальная переносимая игра (лесопилка, ночной экран, синхронное сохранение полного захода, ресурсы и день/сезоны/годы) в этой ветке отсутствует.** Нельзя считать E2E-интеграцию выполненной. Не меняем `main`, старый проект, баланс работы/боя или боевую спецификацию огра/«Огненного шара».

## Утверждённый эффект

После завершения сдачи 15 сломанных копий на **существующем экране ночного сна** появляется дополнительная кнопка `Тренировка`. Одно использование заканчивает **одну существующую ночь**, даёт Силе +1 и Выносливости +1 (каждая в пределах её **текущего** максимума, включая увеличение до 200), восстанавливает HP = 10×текущая Выносливость, ману и энергию до **живых** максимальных значений с учётом бонусов. Негативных эффектов нет. Повторное начисление в ту же ночь и после перезагрузки невозможно. Никакого дополнительного времени (часов, суток сверх штатного перехода), календаря или новых способов сна не создаётся.

## Как подключать к исходной переносимой игре

Из `suslik-2/` на `file://` подключить **обычные скрипты** без Node, ESM, fetch и сервера:

```html
<script src="foreman-spears-core.js"></script>
<script src="foreman-spears-content.js"></script>
<script src="foreman-spears-ui.js"></script>
<script src="foreman-spears-bridge.js"></script>
<script src="foreman-night-training-core.js"></script>
<script src="foreman-night-training-content.js"></script>
<script src="foreman-night-training-bridge.js"></script>
<script src="foreman-night-training-ui.js"></script>
<script src="foreman-spears-host-hooks.js"></script>
<link rel="stylesheet" href="foreman-spears.css">
<link rel="stylesheet" href="foreman-night-training.css">
```

При создании `SUSLIK2ForemanSpearsHostHooks.create(bindings)` в реальном игровом хосте передать уже описанные в `FOREMAN_SPEARS_INTEGRATION.md` bindings лесопилки и `bindings.nightTraining` (ниже), а также **реальные** `showTrainingScene()` и `showExistingDayMap()`. На настоящем ночном экране вызывать `mountHomeNightTraining(buttons, undefined, {locale})`. Этот метод физически не создаёт кнопку, пока квест не завершён, ночь не активна, эта ночь не использована или необходимые host callbacks не подключены. Не передавать фальшивый `onTraining`: старая сигнатура сохранена лишь для совместимости, эффекты теперь строго в утверждённом модуле.

При загрузке сохранения до отрисовки вызвать `initializeExistingSave()` для миграции уже завершённого квеста. Если `resumeNightTraining(view, {locale})` вернул true, отобразилась уже **сохранённая** тренировочная сцена; повторно не заканчивать ночь. После единственной кнопки `Далее` произойдёт сохранение отметки показа и вызов **существующего UI-перехода** `showExistingDayMap()`, который **не должен повторять расчёт ночи**. Если сохранение недоступно, сцена остаётся и бонусы не выдаются.

`bindings.nightTraining` — строгие функции актуального игрового хоста:

| Имя | Требование |
| --- | --- |
| `readSnapshot()` | Возвращает один **отсоединённый от живого state** `{game,quest,training,revision}`. `revision` от штатного сохранения |
| `commitSnapshot({game,quest,training},expectedRevision)` | **Атомарно** сохраняет один снимок, только если ревизия равна `expectedRevision`; `true` при успехе, `false` при ошибке/гонке. Не создаёт новый ключ |
| `readQuestFlags(game)` | Подтверждённое завершение авторского квеста в штатном сохранении |
| `isExistingNightScreen(game)` | Реальное состояние доступной ночной сцены, не новый счётчик |
| `readExistingNightId(game)` | Уникальный стабильный идентификатор **текущей** ночи из штатного прогресса, например штатный составной идентификатор год/сезон/день; новых часов/дней не создавать |
| `readStats(game)`, `readStatCaps(game)` | Текущие Сила/Выносливость и утверждённые пределы для данного захода, включая расширенный максимум 200 |
| `applyTrainingStats(game,{strength,endurance})` | Чисто возвращает НОВЫЙ state, меняя только заданные характеристики |
| `completeExistingNight(game,receipt)` | Чисто вызывает **тот же уже существующий механизм завершения ночи** (сезоны, годы, дневная карта) РОВНО ОДИН раз в расчёте; не выполняет внешних действий до commit |
| `verifyExistingNight(before,after,receipt)` | Подтверждает штатное завершение именно этой ночи, возвращает строго `true` |
| `readResourceMaxima(afterNight)` | Возвращает **живые** максимумы `{hp,mana,energy}` после ночи и бонусов; `hp=10×Выносливость` |
| `applyFullRecovery(afterNight,maxima)` | Чисто создаёт новый game state, заполняя HP/ману/энергию до текущих максимумов, **не добавляя новых эффектов** |
| `readResources(nextGame)` | Проверка реально записываемых HP/маны/энергии |

Смена суток/сезонов/лет, восстанавливаемые бонусные максимумы и доступность ночи **берутся только из настоящего хоста**. Код модуля не пытается их угадать. Установить `training: SUSLIK2ForemanNightTraining.initialState()` при **новом заходе** и хранить поле в **том же** штатном сохранении, что и `game`/`quest`. `training.usedNightIds` хранит уникальные идентификаторы уже использованных тренировочных ночей и исключает повтор при перезагрузке или возврате к старому номеру ночи; `training.lastNightId` хранит последний идентификатор. `training.presentation` содержит выбранные медиа после атомарного начисления. При возврате в ту же сохранённую ночь повторной оплаты нет. Для корректной многовкладочной игры `commitSnapshot` обязан отклонять устаревшие ревизии.

## Медиа (без новых изображений)

В `foreman-night-training-content.js` есть слоты `main` и `detail` с пустыми `variants:[]`. Позднее автор добавляет варианты с постоянными ID и путями (`kind:'image'` для PNG/GIF, `kind:'video'` для MP4/WebM). При **каждой новой тренировке** из каждой непустой группы независимо выбирается вариант равномерным броском; выбор сохраняется как ID, поэтому после загрузки продолжится та же анимация без нового броска. Группы могут содержать один, несколько либо ноль файлов. Пока файлы не предоставлены, вместо них показывается нейтральный пустой слот. Никакие файлы-изображения не создавались.

## Как проверить после публикации полноценного хоста

Завершить квест → дождаться **штатной** ночи → увидеть кнопку «Тренировка» → нажать → проверить сохранённые +1/+1, полные текущие HP/ману/энергию, завершение **одной** ночи → перезагрузить сцену без повторного начисления → «Далее» на дневную карту → следующая настоящая ночь снова предлагает тренировку. Проверить пределы 100 и 200, бонусы энергии, неудачное сохранение, отсутствие квеста и переход через сезон/год по действующим правилам. Изолированные тесты: `node --test tests/foreman-night-training.test.mjs` (Node только в разработке).

**Блокирующие исходники:** `suslik-2/index.html`/`src.js` в GitHub содержат ранние экраны, а не настоящую портативную сборку. Не опубликованы реальный обработчик ночи/дня, домашний UI сна, полноформатное сохранение `game,quest,training` с CAS/ревизией, реальные ограничения характеристик и ресурсные максимумы, завершение ночи/сезонов/лет, используемая музыка. Точные имена этих файлов ещё неизвестны. Для конечной интеграции они должны находиться **в `suslik-2/` с их реальными именами**, без правки старого проекта. Не считать механизм E2E-проверенным до появления актуального игрового хоста.
