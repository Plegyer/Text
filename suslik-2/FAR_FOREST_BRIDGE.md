# SUSLIK 2 — подготовка привязки дальнего леса к лесопилке и бою

**Статус:** интеграционный контракт, **не готовый игровой маршрут**. Основа: `suslik-2/far-forest-goblin-isolated`, PR #314, коммит `471cd4d`. Ревью координатора: https://github.com/Plegyer/Text/pull/314#issuecomment-6146272691. Боевые решения: дословный `COMBAT_LOGIC.md` из ветки `suslik-2/combat-logic-v1`, commit `192c3782f1feeb3a47c9736f7e1ff185d7894011`.

## Публикация и доступные исходники

В опубликованных `suslik-2/intro-v1`, `suslik-2/far-forest-goblin-isolated`, `suslik-2/combat-logic-v1` нет действующей портативной лесопилки, обязательных событий 15/50 смен, реального ночного обработчика, сезонных изображений/зарплат и универсального боевого движка. Поэтому **не** выполняется патч несуществующего экрана и не добавляется фиктивная игра. Всё ниже — проверяемые точки интеграции для координатора, когда текущий код будет опубликован.

## Подключение с диска, без Node.js и fetch

Добавьте рядом с существующими `far-forest-*.js` обычные скрипты в переносимую HTML-страницу, **после** старого `far-forest-core.js`, **до** вызова интеграции:

```html
<script src="far-forest-core.js"></script>
<script src="far-forest-content.js"></script>
<script src="far-forest-ui.js"></script>
<script src="combat-contract.js"></script>
<script src="far-forest-bridge.js"></script>
<link rel="stylesheet" href="far-forest.css">
```

Инициализация: `const bridge = SUSLIK2FarForestBridge.create(bindings)`. Все `bindings` должны делегировать **на реально существующий код**, а не на заглушки с придуманными формулами:

| Binding | Обязательный контракт |
| --- | --- |
| `readSnapshot()` | Снимок одного текущего сохранения `{game, farForest}`, включая общий счётчик оплаченных смен |
| `commitSnapshot({game,farForest})` | **Одна** синхронная атомарная запись обеих частей, `true` только при успехе |
| `readForemanEvidence(game)` | Фактические оплаченные смены, Сила, Выносливость и флаг **завершённого** обязательного разговора |
| `readPaidShiftCount(game)` | Общий настоящий счётчик **оплаченных** смен |
| `canAttemptUsingExistingRules(game)` | Существующий контроль возможности работы; без новых правил энергии/времени |
| `calculateApprovedShift(game,receipt)` | **Чистая** штатная процедура обычной смены: −1 энергия, утверждённые сезонные характеристики, стандартный тариф и **+10 золота**, плюс +1 к общему счётчику смен |
| `verifyApprovedShift(before,after,receipt)` | Проверка выполненного штатного расчёта, возвращает строго `true` |
| `verifyMandatoryEventFlow(before,after,receipt)` | Подтверждает, что существующие события 15/50 и постсменный маршрут сохранены/запланированы. Строго `true` |
| `readHeroCombatState(game)` | *Позже*: текущие HP/мана, maxMana из существующего сохранения, Сила/Выносливость/Ловкость |
| `enterUniversalCombat(request)` | *Позже*: только настоящий универсальный боевой движок, никакого локального исхода боя |
| `applyRestoredCombatResources(game,restored)` | *Позже*: после **уже совершённого** ночного события обновляет только HP/ману, возвращает новое состояние |

### Порядок вызовов

1. Из **callback завершения** обязательного разговора бригадира: `bridge.afterForemanConversation()`. Если 15+ оплаченных смен, Сила ≥ 15, Выносливость ≥ 15 и диалог действительно завершён, в текущем сохранении ставится разблокировка.
2. При рендере лесопилки: `SUSLIK2FarForestUI.addAccessButton(container, snapshot.farForest, onOpen, {locale})`; отсутствие разблокировки означает **отсутствие кнопки**.
3. При начале попытки или «Продолжить работу»: `bridge.beginAttempt()`. Результат одного независимого броска **сразу сохраняется**, поэтому ошибка последующего расчёта не позволяет заново бросить шанс той же попытки.
4. Если исход `ordinary`, вызвать `bridge.settlePendingOrdinary()`; *только после* успешного атомарного сохранения показать штатное сезонное изображение и кнопки `Далее` и `Продолжить работу`. Сохраняется один оплаченный shift и его receipt; до оплаты новый бросок запрещён. При неуспешной записи повторяют **только** `settlePendingOrdinary` того же attempt ID.
5. Из `Далее` отдать управление **существующей** системе обязательных событий (особенно после 50-й оплаченной смены) и штатному post-shift-flow. Модуль не помечает события пройденными автоматически. Хост обязан хранить незавершённое обязательное событие в сохранении для восстановления после перезагрузки.
6. При встрече с гоблином `bridge.chooseGoblin('permission')` или `bridge.chooseGoblin('fight')` сохраняет разные постоянные ID, без оплаты, энергии и времени. Для второго пути `bridge.pendingFightRequest()` возвращает данные первого гоблина; `bridge.enterUniversalCombatIfAvailable()` вызывает только предоставленную `enterUniversalCombat`. Если движка нет, остаётся заглушка `far-forest-fight-pending`.
7. **После** штатного завершения любого сна/ночного события: `bridge.afterExistingNightEvent()`, когда есть реальное сохранение и `maxMana` (её формула не задана). Метод меняет только HP и ману, не энергию/сезон. Его не вызывать до фактического ночного события.

Все доступные игровые ресурсы должны приходить из существующего сохранения. HP = 10 × Выносливость; у первого гоблина 36 HP, 60 урона, Ловкость 1, точность 20; уклонение = clamp(1.25 × (Ловкость защитника − точность атакующего), 0, 100). Магическая атака второй, но **заклинаний пока нет**. Не реализованы точность Амалии, общие ничьи инициативы, автоматические победы/поражения, награды и штрафы — отсутствуют решения автора. Следовать `COMBAT_LOGIC.md`.
