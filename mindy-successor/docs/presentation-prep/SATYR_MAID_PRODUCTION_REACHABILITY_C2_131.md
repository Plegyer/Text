This finalization branch is built directly on the frozen production Satyr runtime. Event and complex-ending presentation slots are no longer created by preparation-only reservation loops: they are generated by the ordinary live-catalog event/ending registry.

The C2-131 regression proves that every published Satyr career, School, crisis and recurring-guest event exists in the production catalog, maps through `presentationIdForEvent(...)` to the exact v12 presentation override, and retains a project-owned static fallback. It also proves all nine persisted career stages and both complex ending identities are present in the real runtime catalog.

A real `satyr-maid.shift` command is executed from a normal started save. The runtime selects `satyr-maid.career.first-shift` and writes the exact production presentation ID `job/satyr-maid/event/satyr-maid-career-first-shift/default` into pending state; animation-off resolution then reaches the exact static override.

No preparation manifest is used as a shipped consumer, and no gameplay/Save/RNG/progression/reward behavior is changed.
