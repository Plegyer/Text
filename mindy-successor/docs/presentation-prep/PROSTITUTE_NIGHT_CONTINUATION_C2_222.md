## Core separation

The voluntary ordinary Prostitute career and Secret Debt forced Night are separate systems.

Current Prostitute runtime publishes no exact Prostitute Night choice/consumer.

Current Secret Debt product structure explicitly requires a mandatory forced Night obligation while bound, but that system is separate from the ten ordinary careers and uses its own hidden-career state.

Therefore C2-222 prepares only voluntary Night presentation semantics.

## Voluntary Night continuation

Prepared semantic meaning:
- optional continuation after ordinary professional work;
- explicit player choice;
- distinct from the daytime/evening `prostitute.shift`;
- distinct from ordinary seasonal shift presentation;
- distinct from Secret Debt forced Night.

Possible future presentation phases:
- Night offer/availability;
- voluntary accept;
- voluntary decline;
- client arrival/continuation;
- adult-only Night work where exact authority allows it;
- non-explicit result/reset;
- return to ordinary Night/day flow.

Every phase remains:
- `PENDING_RUNTIME_ID`

## Required future runtime authority

Production binding requires exact future definitions for:
1. Night choice ID;
2. conditions;
3. selected/declined state;
4. exact adult-only consumer, if any;

Chat 2 does not define any of those mechanics.

## Ordinary shift non-consumption rule

The design draft states that normal work does not automatically consume every Night.

Presentation therefore must not:
- render an ordinary `prostitute.shift` result as if Night were already consumed;
- imply mandatory continuation;
- attach a Night adult asset to ordinary seasonal/default shift IDs;
- visually show a forced transition after every shift.

## Decline-safe presentation

Future voluntary Night decline must remain semantically valid.

It must not imply:
- career failure;
- client anger by default;
- relationship loss;
- consent withdrawal penalty;
- debt activation;
- forced Night fallback.

## Secret Debt forced-night firewall

Secret Debt has a separate fixed product structure:
- hidden bound career;
- ordinary jobs blocked while bound;
- mandatory forced Night obligation;
- forced Night distinct from daytime hidden-career shift;
- next-day modifier semantics owned by NightFlow/runtime authority.

Voluntary Prostitute Night must not reuse those semantics as if they were ordinary-career behavior.

Do not visually imply:
- owner/lender control;
- debt schedule;
- locked exits;
- mandatory escort;
- forced room handoff;
- debt payment ledger;
- unavoidable next-day penalty;
- inability to decline.

Secret Debt presentation consumers, when implemented, must use separate exact identities.

## Priority rule

If a future runtime allows both systems to coexist, forced Night priority belongs to shared NightFlow/runtime authority.

Chat 2 must consume the resulting exact chosen Night consumer only; it must not resolve priority in presentation.
