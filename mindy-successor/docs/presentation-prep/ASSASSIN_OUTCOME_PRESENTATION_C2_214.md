# C2-214 — Assassin outcome visual distinction

Status: COMPLETE PREP ONLY
Owner: Chat 2 / Presentation & Media

## Production ending authority

The only shipped public Assassin ending is:
- gameplay id: `ending.assassin.hard-work`
- presentation id: `ending/assassin/hard-work`

C2-214 preserves this existing ending identity and does not change its eligibility, reward, Meta behavior, or static media.

## Hard Work

Production status:
- `LIVE_SHIPPED`

Visual meaning:
- sustained ordinary Assassin work;
- professional reliability;
- accumulated work experience.

It must remain compatible with the current shipped 50-shift Hard Work rule.

Presentation must not retrofit the design draft's future “several task types” requirement into current gameplay.

## Ghost

Production status:
- `PENDING_RUNTIME_ID`

Draft visual identity:
- controlled preparation;
- low visible trace;
- empty/cleared route;
- precise timing;
- withdrawal without spectacle.

Must not imply:
- current public ending eligibility;
- stealth meter;
- kill count;
- low-fallout mechanic;
- Activity route exists in production;
- reward exists.

Ghost must remain visually distinct from Hard Work: it is a possible advanced-route concept, not “Hard Work with darker art.”

## Handler Takeover

Production status:
- `PENDING_RUNTIME_ID`

Draft visual identity:
- network/control context;
- ledger or contact map;
- handler/rival confrontation;
- evidence and communication rather than target execution.

Must not imply:
- ownership of Merchant/Tavern/Palace systems;
- generic patron/network mechanic;
- automatic handler relationship;
- economy/control reward;
- current ending eligibility.

Handler Takeover must remain distinct from Ghost: control of contacts/network is not the same semantic as low-trace operations.

## Refusal / Turncoat

Production status:
- `PENDING_RUNTIME_ID`

Draft visual identity:
- deliberate refusal;
- warning/redirection;
- evidence disclosure;
- changed allegiance/contact context;
- withdrawal from an order.

Must not imply:
- Morality stat;
- “good” alignment;
- automatic Guard/Palace alliance;
- target-saving gameplay;
- betrayal score;
- current ending eligibility.

Refusal/Turncoat must remain distinct from Handler Takeover: refusing or exposing a network is not the same as controlling it.

## Multiple-readiness boundary

The draft says multiple outcomes may become eligible, but no current runtime publishes Ghost, Handler Takeover, or Turncoat ending IDs.

Presentation prep therefore:
- does not create ending cards for them;
- does not reserve `ending/assassin/ghost`;
- does not reserve `ending/assassin/handler-takeover`;
- does not reserve `ending/assassin/turncoat`;
- does not add reward or Meta identifiers.

All three advanced outcomes remain:
- `PENDING_RUNTIME_ID`

## Palace firewall

Draft Handler Takeover / Turncoat prose mentions possible Palace contacts only as future design context.

C2-214 does not imply or create:
- Palace access;
- Palace contact identity;
- Palace ending requirement;
- Palace reward;
- bypass of existing Palace unlock rules.

## Accessibility distinction

If future runtime authorizes these outcomes, RU/EN alt/caption must describe the concrete scene rather than evaluative labels such as “good”, “evil”, “clean”, or “corrupt.”

The visual distinction should communicate route semantics without judging the player's political/moral choice.

## Firewall

C2-214 creates no new ending, eligibility, reward, Meta mutation, Morality system, combat state, target state, relationship state, network mechanic, Save/RNG, economy, Activity or Palace gameplay.
