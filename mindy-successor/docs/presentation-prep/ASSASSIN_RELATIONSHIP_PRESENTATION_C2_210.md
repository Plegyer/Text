## Draft relationship roles

The Assassin design draft names role families:
- handler;
- rival operative;
- recurring target/contact;
- informant.

C2-210 prepares visual semantics only. No role string becomes a production relationship ID.

## Handler

Prepared visual states:
- first briefing;
- professional trust;
- pressure/disagreement;
- evidence confrontation;
- cooperation;
- refusal respected;
- separation or route divergence.

Must not imply:
- compulsory loyalty;
- romance requirement;
- network ownership;
- automatic Handler Takeover readiness.

## Rival operative

Prepared visual states:
- professional competition;
- mutual observation;
- tension;
- grudging respect;
- temporary collaboration;
- refusal/non-escalation.

Must not invent:
- duel/combat system;
- rivalry score;
- sabotage mechanic;
- Morality judgment.

## Informant

Prepared visual states:
- discreet information handoff;
- incomplete lead;
- uncertain reliability;
- protected identity/context;
- safe refusal or withdrawal.

Must not imply:
- guaranteed intel truth;
- global informant network;
- universal crime contacts;
- automatic Tavern/Guard/Palace access.

## Recurring contact

Prepared visual states:
- repeated meetings;
- changing trust/context;
- professional boundary;
- optional friendship/romance only if future runtime explicitly publishes it;
- betrayal/partnership only if future runtime explicitly publishes it.

Current presentation prep must remain relationship-mode neutral.

## Refusal-safe behavior

Any future refusal state should communicate a deliberate boundary without implying:
- automatic career failure;
- Morality gain/loss;
- forced romance;
- automatic Turncoat progression;
- ending lock;
- money/item punishment.

## Cross-career separation

Assassin relationship presentation must stay distinct from existing:
- Tavern recurring traveler;
- Hunter senior guide;
- Guard partner;
- Merchant supplier;
- Artist/Geisha mentor.

Shared professional-contact framing does not merge semantic identities.
