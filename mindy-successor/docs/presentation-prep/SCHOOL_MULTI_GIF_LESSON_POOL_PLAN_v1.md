# Shared classroom vs teacher-specific pools

## Shared classroom loops

Can be produced before teacher identity approval when they avoid named-character specificity.

Examples:
- classroom/study environment;
- desk/slate/notes;
- neutral practical exercise;
- training/rehearsal environment where track context is already clear.

These remain reusable across multiple semantic IDs.

## Teacher-specific loops

Chat 5 proposes named teacher identities and visual brief seeds.

These are useful authoring inputs but remain CONTENT_DRAFT.

Before final teacher-specific GIF production:
1. teacher content ID must be accepted into current authority;
2. visual brief must be approved;
3. semantic mapping must remain the existing paid lesson ID unless Product explicitly authors a separate teacher event;
4. teacher animation must not create a lesson prerequisite or relationship requirement.

# Track-specific candidate rule

Track-specific media may differ visually while the paid lesson semantic ID remains:

`school/<track>/lesson/default`.

- 1-Energy paid lesson transaction;
- typed paid progress;
- stat package;
- public-result eligibility;
- Night-study progress;
- milestone rules.
