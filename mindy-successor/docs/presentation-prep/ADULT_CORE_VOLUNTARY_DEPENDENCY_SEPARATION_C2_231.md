# C2-231 — Adult core voluntary vs coercive/dependency separation

Status: COMPLETE PREP ONLY
Owner: Chat 2 / Presentation + Media
Production future IDs: PENDING_RUNTIME_ID

## Principle

Voluntary adult/intimacy presentation and coercive/dependency presentation are separate semantic families.

They must never share one generic presentation identity merely because both are adult-themed.

## Voluntary adult/intimacy

Prepared semantic requirements:
- exact voluntary consumer;
- clear player-selected or relationship/route-authorized context;
- no dependency/ownership implication;
- safe/default fallback remains available where required.

Presentation may communicate:
- mutual/private context;
- professional voluntary adult work;
- voluntary Night continuation;
- established partner/relationship intimacy;
- route/ending payoff.

It must not imply:
- debt;
- owner/lender control;
- forced scheduling;
- blocked exit;
- mandatory continuation.

Status:
- `PENDING_RUNTIME_ID`

## Coercive/dependency context

Prepared semantic requirements:
- exact dependency/forced runtime consumer;
- distinct semantic ID family;
- visually explicit loss-of-choice context without borrowing voluntary relationship cues.

Presentation may communicate:
- schedule/control;
- restricted route;
- dependency state;
- aftermath/fatigue;
- locked access where runtime authority says so.

It must not be presented as:
- romance;
- consensual reward;
- generic adult variant;
- relationship progression;
- positive route payoff.

Status:
- `PENDING_RUNTIME_ID`

## Secret Debt precedent

Secret Debt is the current design example of a dependency route.

Product direction already separates it from ordinary voluntary Prostitute work.

Therefore future Secret Debt presentation must remain distinct from:
- voluntary Prostitute adult work;
- voluntary Night intimacy;
- recurring-client relationship scenes;
- route/ending adult payoff.

No shared semantic ID may erase this distinction.

## Relationship boundary

A relationship scene can be:
- professional;
- friendship;
- romance;
- patronage;
- conflict/exploitation.

Adult presentation does not decide which one.

A coercive/dependency relationship must not borrow romance/partner presentation labels unless runtime explicitly publishes a distinct relationship state that warrants them.

## Night boundary

Voluntary Night:
- chosen/authorized by exact Night consumer.

Forced Night:
- intercepted by exact runtime policy.

Presentation must consume the runtime-selected result.

Chat 2 does not decide:
- forced priority;
- lodging suppression;
- next-day penalty;
- calendar advance.

## Ending boundary

Adult ending payoff:
- requires exact ending completion/commitment and future adult payoff consumer.

Dependency ending:
- may be visually adult-themed but must preserve its dependency/route identity.

No ending payoff family may rewrite:
- coercive outcome as consensual;
- voluntary outcome as dependency;
- ending eligibility/reward.

## Fallback rule

Voluntary adult consumer fallback:
- voluntary family fallback;
- then safe static.

Coercive/dependency consumer fallback:
- coercive/dependency family fallback;
- then safe route-specific static.

Never cross-fallback:
- voluntary -> coercive;
- coercive -> voluntary.

## Accessibility rule

Accessibility copy must name context neutrally and accurately.

Avoid labels that:
- romanticize coercion;
- imply consent where none is published;
- infer harm beyond exact runtime semantics;
- erase the difference between voluntary and forced contexts.

## Forbidden assumptions

`NO_AUTHORITY_NOT_BINDABLE`:
- adult asset itself proves consent;
- relationship asset proves romance;
- private room proves voluntary context;
- Night asset proves voluntary context;
- explicit media proves reward;
- coercive route may reuse voluntary adult semantic IDs.

## Firewall

C2-231 creates no consent mechanic, dependency state, Secret Debt mechanic, relationship progression, NightFlow policy, housing rule, ending eligibility/reward, Save/RNG, economy or media binding.
