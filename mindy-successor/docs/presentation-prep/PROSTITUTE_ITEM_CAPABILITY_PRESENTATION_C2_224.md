## Capability boundary

Visual possession does not activate a gameplay capability.

Future production binding requires exact runtime authority for:
- item ID;
- capability ID;
- acquisition/grant;
- exact consuming event/route.

Until then, presentation prep does not invent:
- inventory entries;
- item counts;
- capability strings;
- item-gated presentation IDs.

## Adult/intimacy boundary

No draft item automatically grants adult-content access.

In particular:
- formal attire != adult gate;
- private-room key != adult gate;
- contract/token != consent;
- evidence/document != relationship state.

Any adult/intimacy consumer requires a separate exact adult-only presentation gate.

## Route boundary

Items must not silently collapse late routes:
- formal attire does not equal Elite Clientele;
- private-room key does not equal Independent House;
- evidence/document does not equal Network / Protection;
- contract/token does not equal recurring-client relationship.

Future exact route readiness belongs to runtime authority.

## Secret Debt firewall

Voluntary-career items must not visually imply:
- lender/owner key;
- locked-room control;
- debt contract;
- forced-work schedule;
- debt evidence ledger.

Secret Debt items/state, if published, require separate exact identities.

## Cross-system boundary

C2-224 does not borrow:
- Tavern staff key;
- Guard badge/pass;
- Merchant documents/items;
- Palace credentials.

Existing items from other careers remain owned by their own runtime identities.

## No reserved IDs
