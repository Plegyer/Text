## Batch choice

The first batch follows priority #1: **repeatable ordinary-career shifts**.

Produce exactly **30 unique GIF files**:
- 3 neutral repeatable loops per ordinary career;
- each career-specific trio is reused across that career's four seasonal shift semantic IDs;
- no loop contains season-specific outcome/mechanical information.

This is the smallest honest set that can make all **40 ordinary-career seasonal shift pools** valid at PR42's minimum size of 3 while keeping the visuals career-specific.

The 10 career result slots are intentionally not claimed by this batch. Poverty, School and Forest remain the next priorities after this high-value repeatable-work wave.

## Candidate-key convention

For import, use stable locale-neutral keys matching the file stem:
- `<career>-shift-01`;
- `<career>-shift-02`;
- `<career>-shift-03`.

The same three candidate keys/files may be mapped to spring/summer/autumn/winter slots for the same career. The semantic `presentationId` remains different for each season.

## Production constraints

Every GIF in this batch must:
- be a real repository asset before activation;
- loop cleanly without controlling gameplay duration;
- avoid displaying a success/failure/reward that the shift did not determine;
- avoid season-specific cues if it is to be reused across all four seasons;
- use one locale-neutral file for RU and EN;
- receive RU+EN alt text at integration time;
- retain the existing static SVG fallback;
- never participate in gameplay RNG, conditions, rewards, effects, eligibility or Save identity.
