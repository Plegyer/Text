# C2-208 — Assassin method presentation preparation

Status: COMPLETE PREP ONLY
Owner: Chat 2 / Presentation & Media
Production binding: NONE

## Prepared method families

The Assassin design draft names several possible method families. C2-208 treats them as visual/presentation concepts only.

### Stealth
Presentation cues:
- empty route;
- shadowed entrance;
- timing notes;
- quiet movement;
- concealed access preparation.

Must not imply:
- stealth meter;
- invisibility state;
- guaranteed success;
- combat avoidance mechanic;
- lethal/nonlethal result.

### Social access
Presentation cues:
- formal or context-appropriate clothing;
- invitation/document review;
- public entrance;
- conversation or reception setting.

Must not imply:
- automatic persuasion;
- Palace access;
- universal social status;
- Seduction mechanic;
- romance requirement.

### Staged
Presentation cues:
- environment setup;
- route timing;
- object placement;
- neutral scene preparation.

Must not depict or imply a specific injury/death mechanic.

### Indirect
Presentation cues:
- rerouted note;
- changed schedule;
- intermediary contact;
- altered path;
- evidence/document handoff.

Must not imply:
- poison system;
- trap system;
- remote combat;
- generic manipulation stat.

### Refusal / alternative resolution
Presentation cues:
- closed contract;
- warning note;
- withdrawal;
- redirection;
- evidence retained or passed on.

Must not present refusal as:
- automatic failure;
- Morality gain/loss;
- guaranteed Turncoat progression;
- permanent career lock;
- free ending eligibility.

## Non-combat default

Assassin presentation prep defaults to:
- preparation;
- route;
- information;
- equipment;
- environment;
- consequences.

Explicit combat depiction is not required by current production authority and must not be invented by Chat 2.

## No Morality presentation system

C2-208 must not create:
- good/evil color coding;
- morality meter;
- saint/criminal alignment;
- refusal virtue score;
- lethal/nonlethal morality score.

If future runtime publishes method-specific facts or states, presentation must use those exact identities without adding evaluative alignment.

## Availability boundary

A visual method family does not assert that a player can choose that method.

Future production binding requires exact runtime authority for:
- method ID;
- eligibility;
- phase;
- result/fallout identity.

Until then all method families remain:
- `PENDING_RUNTIME_ID`

## Firewall

No gameplay method, combat rule, success chance, condition/effect, item capability, Save/RNG, ending route, Guard/Palace state, Morality or reputation system is changed or created.
