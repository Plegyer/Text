# GIF Exporter Dependency Integration Acceptance v1

Scope:
Lead-owned integration of the deterministic presentation GIF exporter.

Exporter source:
`prior-work/astra/prototype-m3.2/tools/export-presentation-gif.mjs`.

Required exact dev dependencies:
- `sharp@0.35.4`;
- `gifenc@1.0.3`.

## Package acceptance

Only acceptable package changes:

### package.json
Add exact `devDependencies`:
- `sharp: "0.35.4"`;
- `gifenc: "1.0.3"`.

Add authoring script:

```json
"media:export-gif": "node tools/export-presentation-gif.mjs"
```

Neither package may be added to runtime `dependencies`.

### package-lock.json
Must be generated by npm from the approved package.json.

No hand-authored integrity/platform/transitive entries.

## CI environment acceptance

Baseline:
- Ubuntu GitHub runner;
- Node 22.18.0;
- `npm ci`;
- full `npm run check`.

Required:
1. `npm ci` succeeds on exact integration head;
2. sharp native/platform package resolves without manual external CLI dependency;
3. gifenc import/API resolves;
4. exporter dry-run works;
5. source/static tests still pass;
6. exact-head CI passes.

## Exporter smoke acceptance

Use one existing Lumber spring source sequence only:

- semantic ID:
  `job/lumber/shift/spring/default`;
- sequence:
  `lumber-spring-work-loop-a`;
- 4 local project-owned SVG frames.

Smoke target:
- 640×360;
- 600 ms/frame;
- 2400 ms total loop;
- loop count 0;
- <=256 colors.

Required smoke checks:
- exporter resolves exact manifest sequence;
- source order is deterministic;
- no external resource access;
- GIF validator confirms signature/dimensions/frame count/timing/loop;
- output stays under approved technical budget.

## Deterministic same-input acceptance

On the same pinned Node/OS/lockfile/exporter/source environment:

1. export the same sequence twice with identical arguments;
2. compare byte size;
3. compare SHA-256;
4. require byte-for-byte equality.

Failure to achieve same-environment byte identity blocks production pool activation until investigated.

Cross-platform byte identity must not be assumed without evidence.

## Runtime isolation acceptance

The dependency PR must not modify:
- application runtime imports to include sharp/gifenc;
- shared presentation schema/runtime/UI;
- gameplay;
- Save;
- content conditions/effects/rewards;
- root GIF pool mappings.

The exporter is authoring-only.

## Production pool gate

Even after dependency integration succeeds, production GIF pool activation remains blocked until for each candidate:

1. actual GIF bytes exist;
2. technical validator passes;
3. source/provenance ledger is complete;
4. candidate alt localization exists in RU+EN;
5. static fallback exists;
6. 3–5 candidate pool is complete;
7. deterministic candidate selection remains locale-neutral;
8. full exact-head checks/CI pass.

A successful exporter smoke is not a production pool.

## Rollback

If native install/CI/reproducibility fails:
use `GIF_EXPORTER_ROLLBACK_PACKET_V1.md`.

Rollback must remove only package/script integration and smoke bytes.

Project-owned SVG frame sources/static fallbacks remain valid.

## Acceptance decision

Lead may mark dependency integration **ACCEPTED** only after:
- exact versions pinned;
- npm ci passes on Node 22;
- smoke export passes;
- same-input output is deterministic;
- no runtime dependency leaked in;
- full checks/CI pass.

Until then:
**DEPENDENCY_PR_REQUIRED / NOT ACCEPTED**.
