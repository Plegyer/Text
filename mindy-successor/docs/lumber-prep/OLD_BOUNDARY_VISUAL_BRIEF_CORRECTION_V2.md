# Old-Boundary Visual Brief Correction v2

Status: safe replacement visual brief for future project-owned old-boundary static/GIF source.

Gameplay route:
`forest.route.old-boundary`.

Route state:
`old-boundary`.

Semantic presentation ID:
`activity/forest/route/old-boundary`.

This brief corrects earlier over-specific source imagery. It does not activate any asset.

## Safe visual target

Primary read:
an old path-boundary line expressed through natural terrain and aged human markers.

Required visual ingredients:
- moss-covered boundary stones;
- weathered cuts or marks on tree trunks;
- a narrow stony path/line;
- repeated stone/mark rhythm;
- ordinary forest vegetation;
- less-worked terrain than the modern logging road.

The route should look old and legible without looking mechanically locked.

## Explicitly exclude

Do not depict:
- constructed arch;
- gate;
- fence;
- checkpoint;
- turnstile;
- barrier mechanism;
- keyhole;
- token slot;
- pedestal waiting for an item;
- toll point;
- Hunter insignia;
- Hunter NPC;
- School/Arcana symbol;
- glowing magic;
- challenge reward;
- treasure;
- hidden destination reveal;
- route-completion reward.

## Token firewall

The visual must not imply how `enter_old_boundary` is obtained or used.

Do not show:
- an Old Boundary Token;
- a hand inserting an item;
- an item being surrendered;
- an item being consumed;
- a marked payment exchange.

The existing gameplay capability gate stays invisible to presentation unless Product later defines a canonical visible interaction.

## Lore firewall

The image may show evidence that people marked the area long ago.

It must not answer:
- who made the stones;
- why they were placed;
- whether the line is legal/territorial;
- whether it is ritual/magical;
- whether Hunters use it;
- whether it leads to a hidden reward.

Ambiguity is a feature of the safe brief.

## Static composition

Preferred:
- one or more low mossed stones in foreground/midground;
- another marker visible deeper on the same rough line;
- weathered tree mark off-center;
- no obvious man-made barrier silhouette;
- route remains physically walkable.

Avoid a single dominant structure that reads as an entrance gate.

## GIF opportunities

Safe subtle motion:
- leaves moving;
- grass/moss shifting in wind;
- light moving across old stones;
- slow camera drift revealing successive markers.

Unsafe motion:
- gate opening;
- token activation;
- magical glow;
- reward reveal;
- Hunter arrival;
- challenge prompt animation.

## Accessibility direction

Alt text should say what is visible:
old boundary stones, weathered marks, forest path.

Caption may say the markers form an older line than the logging road.

Neither alt nor caption may state token mechanics or deeper lore.

## Fallback rule

Until a corrected project-owned old-boundary asset exists:
use the neutral shipped
`activity/forest/route/default`
static fallback.

Do not activate an over-specific old-boundary source merely because a route-specific seam becomes available.

## Acceptance rule

A future old-boundary asset is semantically safe only when it communicates:
**old stones + old marks + path boundary**

and nothing mechanically stronger.
