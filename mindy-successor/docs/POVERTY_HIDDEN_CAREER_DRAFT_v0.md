# Hidden Poverty Career — design draft v0

Дата: 2026-09-25.

Статус: **USER-DIRECTED DESIGN DRAFT**.

Основание:
- LIFE-05 / LIFE-07 / LIFE-12 / LIFE-14 из `USER_VISION_AND_ACCEPTANCE.md`;
- прямое решение пользователя: бедность должна превращаться в скрытую работу/зависимость по типу рабства, с потерей энергии и обязательной ночной секс-работой;
- прямое решение пользователя: у этой ветки должно быть не меньше трёх разных исходов/наград, включая расплату деньгами, окончание без выхода из зависимости по типу «Упорного труда» и убийство рабовладельца с занятием его места.

Этот документ фиксирует форму системы и обязательные outcome families. Точные числа, тексты, персонажи, пороги и meta rewards пока не утверждены.

---

## 1. Роль системы

Бедность — не просто штраф `нет денег -> плохой сон`.

Она может перевести героиню в отдельную скрытую карьерную систему, где:
- экономическая проблема становится образом жизни;
- дневное время и ночи начинают конкурировать за ограниченную Energy;
- появляются собственные персонажи, отношения, задания и выходы;
- часть обычной жизни становится труднее или недоступна;
- одновременно открывается уникальный контент и альтернативные способы развития.

Это реализует LIFE-05: бедность должна создавать другой жизненный маршрут, а не только ухудшать цифры.

## 2. Это не обычная профессия из 10

Hidden Poverty Career существует ортогонально обычным профессиям.

Она:
- не занимает один из 10 ordinary job slots;
- может возникнуть у героини любой профессии;
- может временно ограничить обычную работу/школу/ночные действия;
- может пересекаться с обычной career progression;
- имеет собственные endings и meta rewards.

Вопрос, должна ли её «упорная» концовка засчитываться в общий Hard Work progress для открытия 11-й профессии, остаётся OPEN и требует отдельного решения.

## 3. Вход в зависимость

Exact trigger пока OPEN.

Поддерживаемые варианты входа должны включать комбинацию экономических условий, например:
- невозможность оплатить ночлег;
- долг выше порога;
- повторные ночи без денег;
- добровольное принятие опасного предложения ради немедленного спасения;
- сюжетный переход из другого poverty event.

Вход не должен быть случайной ловушкой без понятного предупреждения.

Перед commitment игрок должен понимать хотя бы:
- что это долговая зависимость;
- что она ограничит ночи;
- что часть заработка/ресурсов будет уходить на обязательства;
- что выйти можно, но это отдельная progression.

## 4. State model

Предлагаемый typed domain:

```text
PovertyCareerState
  stage:
    free
    precarious
    offered
    bound
    buyout_ready
    endurance_ready
    revolt_ready
    resolved

  debt
  nightsWorked
  moneyPaidTowardFreedom
  compliance/resistance counters?   [OPEN]
  ownerRelationship/state?          [OPEN]
  allyFacts
  choices
  outcomeEligible[]
```

Не реализовывать это generic boolean flags.

## 5. Ежедневная механика bound-state

Когда `stage = bound`:

### День
- обычные дневные actions остаются возможны настолько, насколько позволяет Energy;
- система может удерживать часть дохода или автоматически направлять её в debt;
- некоторые варианты жилья/работ/школы могут измениться;
- специальные poverty actions могут появляться как отдельные choices.

### Ночь
Hidden Poverty Career получает forced-night право.

Типовой flow:

```text
EndDayRequested
-> Poverty before_lodging check
-> mandatory work night
-> result/consequences
-> NextDayModifier
-> CalendarAdvance
```

По прямому решению пользователя ночная работа обязательна в состоянии зависимости.

Архитектурно она использует `NightFlow before_lodging`, чтобы:
- не списывать обычный rent поверх уже перехваченной ночи;
- не показывать normal voluntary-night menu;
- не увеличивать день дважды.

### Energy consequence

Ночная занятость должна уменьшать доступную Energy следующего дня.

Точная величина НЕ фиксируется этим документом.

Предпочтительно:
`AddNextDayModifier(energyDelta = configurable negative value)`.

Не менять permanent base Energy.

## 6. Ночная секс-работа

Это forced labour внутри системы зависимости, а не обычная romance reward route.

Системно она должна:
- занимать ночной слот;
- влиять на next-day Energy;
- продвигать poverty counters/stages;
- иметь варианты по season/context/stats/history;
- иногда создавать внешние знакомства, предметы, слухи, debts/favors или quest facts;
- не путать открывшийся вариант контента с добровольным романтическим выбором героини.

На этапе архитектуры не нужны откровенные тексты/изображения.

## 7. Минимум три обязательных outcome families

### A. Выкуп свободы — `paid_freedom`

Идея пользователя: героиня расплачивается деньгами.

Условия должны требовать реального экономического достижения:
- накопить/выплатить требуемую сумму;
- возможно закрыть дополнительные обязательства;
- не просто один раз нажать кнопку после дешёвого порога.

Финал:
- зависимость прекращается;
- run может продолжиться или ending может быть предложена по общему ending flow;
- poverty content больше не forced.

Тип meta reward:
**экономический / антидолговой / стартовый финансовый**.

Exact reward OPEN. Не фиксировать сейчас бесплатный rent, огромную сумму или постоянное снижение цен без economy review.

### B. «Осталась» / Poverty Hard Work analogue — `bound_life`

Идея пользователя: героиня не вышла из рабства, аналог простого «Упорного труда».

Это не failure screen.

Она сознательно завершает жизнь в этой системе после большого стажа/прогресса.

Условия:
- значительное число ночей/дней в зависимости;
- достижение карьерной вехи;
- отсутствие необходимости победить owner route.

Финал:
- героиня остаётся в своей новой жизни;
- это полноценная ending family;
- награда выдаётся только после commitment/completion.

Тип meta reward:
**опыт/знание этой социальной среды, уникальный старт или доступ к скрытому poverty content в следующих жизнях**.

Exact reward OPEN.

Важно: считать ли это общим `Hard Work` для разблокировки 11-й профессии — OPEN.

### C. Переворот — `takeover`

Идея пользователя: героиня убивает рабовладельца и занимает его место.

Это сложный route, а не простой стаж.

Он должен требовать комбинацию систем:
- достаточный progression внутри hidden career;
- подходящий build;
- внешнее условие/предмет/союзник/информация;
- осознанный route choice.

Финал:
- прежний хозяин устранён;
- героиня занимает его место/контроль над заведением или сетью;
- ending должна ощущаться принципиально иной, чем просто выкуп.

Тип meta reward:
**сильный status/rule-changing unlock или доступ к новой стартовой/властной возможности**.

Exact reward OPEN и должен быть сильнее по масштабу, чем простая стажевая награда.

## 8. Ветки не должны быть одной шкалой

Нельзя строить:
`10 ночей -> A, 20 -> B, 30 -> C`.

Минимально:
- paid_freedom опирается прежде всего на economy;
- bound_life — на endurance/stay progression;
- takeover — на отдельную цепь условий и решений.

Так три endings проверяют разные способы игры.

## 9. Cross-system hooks

Hidden Poverty Career должна иметь связи как минимум с:

### Economy / housing
Причина входа, debt, выплаты, альтернативы ночлега.

### Ordinary jobs
Работа может помогать выкупу; зависимость может урезать доступное дневное время.

### School
Учёба конкурирует за Energy/money, но некоторые знания могут открыть вариант выхода или takeover route.

### Relationships
NPC может:
- помочь выплатить долг;
- дать информацию;
- стать союзником;
- открыть отдельную сцену/route.

Не сводить всё к одному rescue NPC.

### Items
Нужен минимум один meaningful item hook:
- документ;
- ключ;
- оружие;
- компромат;
- ценность для выкупа;
- другой предмет, меняющий доступное действие.

Конкретный item OPEN.

### Large Activity
Результат внешней Activity может дать ресурс/fact для одного из сложных exits.

Это хороший тест межсистемной глубины LIFE-10/11/12.

## 10. Ending flow

Все три outcome families используют общий target pattern:

```text
requirements
-> ending eligible
-> player commitment
-> central/route-specific completion
-> RunResult
-> exactly-once Meta reward
```

Получение суммы денег или убийство owner не должны случайно завершать run в середине команды без commitment, если только конкретный route не будет позже явно определён как terminal forced ending.

## 11. Reward hierarchy

Минимальное правило масштаба:

- `paid_freedom`: reward за экономическое преодоление;
- `bound_life`: reward уровня обычной устойчивой карьерной судьбы;
- `takeover`: reward за сложную multi-system ветку, допускается rule-changing reward.

Нельзя автоматически давать +daily Energy как универсальную награду: пользователь уже отвергал слишком сильный ежедневный бонус за лёгкую трудовую концовку.

## 12. Acceptance examples

Система не считается реализованной, если существует только:
`нет денег -> forced scene -> -1 Energy`.

Минимальная продуктовая проверка:

1. Героиня попадает в зависимость из-за экономики.
2. Forced night действительно перехватывает normal lodging/night.
3. Следующий день имеет меньше Energy.
4. Обычная работа помогает копить на свободу.
5. Одновременно развивается независимая poverty progression.
6. Хотя бы одно внешнее действие (school/item/relationship/activity) меняет доступную ветку.
7. Все три mandatory outcome families могут стать eligible разными путями.
8. Eligibility не выдаёт meta reward.
9. После commitment каждая ending создаёт различный RunResult.
10. New Run показывает эффект соответствующей meta reward.
11. Save/load внутри bound night не дублирует debt/payment/reward/calendar advance.
