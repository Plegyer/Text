# School Post-Decision Implementation Map v1

Status: implementation/content sequence for use after Product answers the School decision packet. Unanswered values stay OPEN.

## 1. Teacher identities and content

Inputs:
- approved teacher/presenter IDs;
- track assignments;
- relationship-role policy;
- presentation priorities.

Expected production domains:
- School teacher/content packs;
- repeatable lesson content;
- presentation/media mapping;
- relationship-owned reaction content only when separately approved.

Validation:
- teacher/course mapping;
- stable semantic presentation IDs;
- no change to tuition, Energy, stat packages, Lust behavior, or School counters;
- reload-safe presentation and fallback.

## 2. Management/accounting milestone and public result

Inputs:
- approved School-owned provider;
- owning track;
- milestone form;
- exact threshold/value if applicable;
- canonical public result ID and publication timing.

Expected production domains:
- School milestone/provider content;
- School public-result content;
- Lumber management consumer;
- result presentation.

Validation:
- exact eligibility;
- exactly-once publication;
- reload before/after publication;
- no payment/progress replay;
- downstream reads public state only;
- Lumber Hard Work remains independent.

## 3. Arcana / Forest result if retained

Inputs:
- explicit scope decision;
- Arcana provider/milestone;
- threshold/value;
- public result;
- exact Forest consumer.

Expected production domains:
- Arcana milestone/provider content;
- School public-result content;
- Forest option/condition content;
- presentation mapping.

Validation:
- exactly-once publication;
- reload-stable Forest availability;
- no private School counter reads;
- Arcana paid mechanics unchanged;
- later Forest Activity result remains Activity-owned.

## 4. Milestone / project / certificate / exam scenes

For each approved unit:
- freeze canonical ID;
- author eligibility/completion;
- author scene/result;
- add presentation;
- add public publication only if approved;
- test completion and reload exactly once.

## 5. Career / Activity consumers

After a School public result is frozen:
- author downstream condition/listener;
- keep downstream state mutation downstream-owned;
- test immediate reaction and reload;
- reject direct reads of School-private counters.

## 6. Presentation / GIF follow-up

After semantic IDs and content are stable:
- add text fallback;
- add static fallback;
- add optional GIF;
- add alt text;
- verify media timing never controls gameplay.

## 7. Acceptance and regression

Always retain:
- all eight paid-course parity;
- all 24 Night-study choices;
- paid/Night counter isolation;
- blocking School scene ordering;
- old-save School defaults;
- long-Save preservation;
- no-false-green coverage;
- Hard Work independence.

Runtime/schema work is created only when an approved authored behavior cannot be represented and a concrete failing integration test proves the missing primitive.
