# Relationship Activity-Return Scene Bank v1

Date: 2026-09-27
Status: RU+EN EFFECT-FREE REACTION BANK

All examples below require the same exact authoritative trigger:

`activityResult(activity=lumber.forest, outcome=success, result=lumber.forest.success)`

No new Activity result is invented. The Forest result is not renamed, broadened, or rewritten. These are 0-daytime-Energy relationship reaction patterns only.

## 1 — Practical acknowledgment
RU: «Ты вернулась с завершённой экспедицией. Хорошо. Сначала зафиксируем, что уже известно, а потом решим, что это меняет для нашей работы».  
EN: “You came back from a completed expedition. Good. First we record what is actually known, then decide what it changes for our work.”

## 2 — No second test
RU: «Если результат уже получен в лесу, здесь не нужно устраивать ему вторую проверку ради разговора. Достаточно признать итог и продолжить».  
EN: “If the result was already established in the Forest, we do not need to test it a second time just for this conversation. We can acknowledge it and continue.”

## 3 — Work-focused return
RU: Бригадир выслушивает короткий отчёт и не приписывает экспедиции нового смысла. «Понял. Тогда посмотрим только на то, что относится к артели».  
EN: The Foreman hears the short report without assigning the expedition a new meaning. “Understood. Then we will look only at what matters to the crew.”

## 4 — Safe boundary
RU: «Лес дал свой результат. Этот разговор может на него отреагировать, но не должен переписывать, как именно он был получен».  
EN: “The Forest produced its result. This conversation can react to it, but it should not rewrite how that result was reached.”

## Authoring rule

A production event using these patterns must name the exact Activity ID, outcome, and result ID in its authoritative typed trigger. The relationship scene adds no Activity cost and normally no daytime Energy cost. Any new relationship effect or deeper meaning requires separate approval.
