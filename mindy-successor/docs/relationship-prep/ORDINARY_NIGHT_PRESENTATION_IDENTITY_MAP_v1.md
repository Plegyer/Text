# Ordinary Night Presentation Identity Map v1

Date: 2026-09-27  
Status: **PRESENTATION/AUTHORING MAP — CURRENT + SAFE PROPOSALS**  
Scope: ordinary voluntary relationship Night only

This map records semantic presentation identities and bilingual text-key coverage without creating media assets. A proposed identity or key is not shipped merely because it appears here. Placeholder GIF paths are intentionally absent.

## Rules

- One gameplay event owns one locale-neutral semantic `presentationId`.
- RU and EN share gameplay/event/relationship IDs and media candidate selection.
- Text and accessibility copy use locale-neutral keys with `ru` and `en` values.
- A future 3–5 GIF pool sits beneath the semantic `presentationId`; it does not create 3–5 gameplay events.
- Current static/text fallback remains valid.
- Captions are authoring keys for future presentation integration where supported; current UI consumes localized media `alt`, not a generic caption field.
- Secret Debt / forced Night presentation is outside this map.

## Localization coverage policy for proposed surfaces

For any productionized event, the minimum bilingual keys are:

- event title;
- every player-visible variant body;
- every player-visible choice label;
- choice result/source text where surfaced or logged for the player;
- media alt for every current media identity;
- caption when/if the presentation surface consumes captions.

English must be a full equivalent, not a placeholder. Missing English on new post-lock relationship content is not normal fallback behavior.

## Static fallback policy

A proposed relationship event does not need a new asset to be valid. Safe order is:

1. real relationship-specific static/GIF content if approved;
2. an existing semantically suitable static fallback;
3. the presentation slot fallback chain;
4. text-only.

This document names no new asset path. Consequently no proposed GIF or still can be mistaken for shipped media.

## Locale and candidate stability

For a future GIF pool under any mapped identity:

- candidate keys are locale-neutral;
- RU/EN share the same pool;
- locale switching keeps the same selected candidate;
- media selection consumes no gameplay RNG;
- a media candidate never changes event variant, relationship state, effects, housing result, or Night transaction;
- save/reload keeps the resolved gameplay/pending identity stable.
