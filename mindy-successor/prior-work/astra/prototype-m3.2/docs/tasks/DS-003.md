# DS-003 — чайные встречи с Браном

Создай пакет ds-bran по docs/contracts/DS-003.json и content/pack.schema.json.
Allowlist: content/packs/ds-bran.json, tests/ds-bran.test.ts,
docs/tasks/DS-003-report.md. Не переписывай base.invite и модель отношений.

Три события: две однократные сцены и повторяемый обед с четырьмя постановками.
Бран — взрослый курьер 27 лет, добродушный, неловко организованный; героиня взрослая.
Первая сцена после bran.met И после принятого решения (bran.date ИЛИ bran.declined).
Вторая после ds.bran.first. Они пишут только ds.bran.first и ds.bran.second.
Триггер visit, priority 5. Никаких новых NPC, концовок, наград или предметов.

Однократные сцены имеют одну общую нейтральную постановку и выборы; явный флирт
доступен только при bran.date=true И bran.declined=false. Дружеский выход есть всегда.
В повторяемом обеде 4 постановки: две дружеские, две романтические с теми же
условиями. Одну дружескую сделать универсальной fallback. Не предлагать новый
романтический выбор после отказа. Тон: тёплый юмор, без давления и откровенности.

Постановка 60–120 слов. Медиа только base.town/base.workshop; новые иллюстрации
описать в отчёте. maxShows повторяемого 4, cooldownDays 14, variantCooldownDays 56.
Прибавки не больше 2; trust пока общий показатель доверия в лавке, поэтому не
объявлять его отдельной любовью Брана и не ставить высокие пороги этой метрики.

Тесты: дружеский и романтический маршруты; после bran.declined нет подходящих
романтических постановок/выборов; порядок вех; один и тот же обед не повторяется
раньше cooldown; загрузка сцены сохраняет постановку.

Готовность: npm run check:package -- DS-003 и npm run check. Отчёт и commit.
