# Распределение работы — 2026-09-24

Это распределение ответственности, не обещание доступности конкретной модели в подписке и не сравнение тарифов. Выгоду считать по принятому результату: подготовка задания + исполнение + исправления + проверка + ручная передача. Не выдавать заранее проценты экономии без измерений.

DeepSeek/Cline: небольшие текстовые пакеты по одной сцене за запрос, варианты постановок и простые замены в заранее заданных полях. Не поручать каждый раз исследование проекта. Сохранять частями, держать контекст замкнутым.

SOL в доступной пользователю среде: основной разработчик ограниченных задач — сборка контента по схеме, тесты, локальные исправления UI, отдельные модули по согласованному контракту. Обычный чат не имеет автоматически доступа к пользовательскому Cline/диску; передавать снимок файлов и получать архив/diff. Если нет запуска, результат непроверен до реального прогона.

Astra: изменение схемы сохранений, общих правил событий, зависимостей систем и экономики; сложные регрессии; периодический обзор крупных вех. Не использовать как обязательного посредника для каждого текста. Механические проверки выполняют скрипты, а не модель пересказывает JSON. Для обычного контентного пакета достаточно прогона и локального ревью; эскалация при новом общем правиле или неустранённом дефекте.

Единая основная копия проекта и интегратор. Авторы работают в отдельных снимках, не одновременно в общих файлах. Передача: ID задачи, базовая версия, чтение, allowlist записи, готовые данные, критерии, точка продолжения. Приёмка относительно базы, затем один merge/checkpoint. Непроведённые тесты не считать успешными.

Пилот: DS-004A/B написаны DeepSeek; SOL-001 собирает три игровых события и тесты; интегратор проверяет контракт и прогон. Замерить число попыток, время до готового файла, объём ручных правок и успешность проверки. Только после этого расширять задачи SOL, не масштабировать ещё не проверенный процесс.
