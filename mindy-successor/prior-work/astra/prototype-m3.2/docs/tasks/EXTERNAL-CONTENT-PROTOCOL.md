# Протокол внешнего производства v2 — 2026-09-24

## Почему меняем
DS-004–006 совмещали сценариста, разработчика событий, автора интеграционных тестов и участника Git-процесса. Ссылки на AGENTS/WORLD/редактор/схему и helpers не задавали замкнутого набора знаний. Требование пройти игру в тесте вынуждало изучать движок, приоритеты и каталог. Корневые инструкции дополнительно требовали README/STATUS/ARCHITECTURE. Allowlist ограничивал запись, но не чтение. Даже DS-007 привязывал простую редактуру к каталогу и тестовым зависимостям. Это чрезмерная самостоятельность для роли массового автора.

Ошибки output-token limit и таймаут не доказывают непригодность модели и не позволяют определить причину без журналов API. Уменьшение входного контекста не устраняет отдельные лимиты вывода, длительности и инструментального протокола. Здесь меняется управляемая часть — размер и неопределённость задания, без обещания исправить провайдера.

## Новый договор
Интегратор выдаёт самостоятельный каталог: локальные AGENTS, TASK, CONTEXT и заготовленный result. Исполнитель читает ровно эти 4 маленьких файла; не получает исходники игры. Ссылок на внешние справочники, «найди аналог», выбор архитектуры или создание тестов нет. Все сюжетные входы, выходы и неизменяемые ID уже определены. Исполнитель пишет только разрешённые строковые поля одного файла. Частичный результат сохраняется по одному объекту. Новый запуск продолжает непустой файл, не пересоздаёт его.

Инструкции о чтении — договор, не техническая песочница. Поэтому открывать отдельную executor-папку вне проекта, а не пытаться запретами сдерживать агента внутри большого репозитория. Не менять глобальные правила Cline/провайдера и не обещать фиксированный общий токен-бюджет. При конфликте инструкций — конкретный блокер.

Интегратор отдельно проверяет форму, текст и связность; преобразует в текущую схему; пишет сценарные тесты; проверяет Git/diff, баланс, сохранения и приоритеты; выпускает checkpoint. Исполнитель не объявляет непроведённые проверки успешными. Результат контентной задачи — текст, а не отчёт о процессе.

## Размер и разбиение
Ориентир авторского контекста — до 10–12 КБ UTF-8, результата — до 8 КБ, 1–3 коротких сцены за задачу. Это байты, не обещание числа токенов. При нестабильном сервисе сохранять одну сцену за инструментальную запись; при повторном обрыве выдавать одну сцену за запуск. Измерять время до первой сохранённой сцены, число чтений, размер результата, число повторных попыток и долю принятых текстов. Не просить модель генерировать длинный план до редактирования.

| Старое задание | Новый выпуск |
|---|---|
| DS-004: 3 события × 3 варианта + тесты + отчёт | DS-004A: три базовые сцены; затем B: шесть сезонных текстов, при необходимости по 3; механика/тесты централизованно |
| DS-005: четыре сезонных события × 3 варианта | Один сезон на пакет: базовый текст и две заранее обусловленные версии; фиксированные выборы/эффекты |
| DS-006: знакомство, приглашение, развязка | Сначала базовые сцены с фиксированным согласием/отказом; альтернативные постановки отдельно; проверка отказа централизованно |
| DS-007: восемь постановок и разработка тестов | Уже принят, не повторять. В дальнейшем по одной профессии × 4 сезона, только текстовые поля |

Конкретный готовый следующий пакет — delegation/DS-004A. Старые DS-004–006 остаются техническими справочниками интегратора; больше не выдавать их как запросы исполнителю. DS-004A не притворяется завершением всех девяти постановок старого задания.
