# Архитектура v1

src/core: чистые функции и типы, без DOM, Electron, файлов и системного времени.
content/packs: декларативные пакеты. Условия all/any/not + численные пороги, флаги,
сезон, жильё, наследие. Последствия только из фиксированного белого списка.
src/ui: локальный интерфейс; не меняет state напрямую, отправляет команды ядру.
desktop: Electron, изолированный preload, сохранение одного атомарного конверта.
scripts: сборка, проверка пакетов, checkpoint; tests: воспроизводимые сценарии.

Run и Meta — разные разделы одного SaveEnvelope: это делает принятие судьбы и выдачу
награды одной записью. Старое сохранение не может затереть заработанный профиль:
при ручной загрузке объединяем постоянные открытия текущего и загруженного профиля.
Слоты и облачная синхронизация пока не входят в M1.

Команда возвращает новое состояние или ошибку. Стоимость/последствия/время
транзакционны. Пока открыта сцена, другое действие заблокировано. Выбор сцены
разрешается без дополнительного времени (стоимость заложена в исходном действии).
События проверяются после действия. День меняется только отдельной командой sleep. Последний день ограничен 448 или 560 днями в зависимости от наследия.

Базовый игровой цикл: действие -> сцена при наличии -> выбор -> окончание дня.
Регистрация судьбы не завершает жизнь. Принятие завершает, выдаёт наследие ровно
один раз и открывает финальный эпилог. Новая жизнь сохраняет Meta.

В M1 не было рандома. M3 добавляет сохранённый RNG для явно вероятностных событий.
Полный календарь существует, но его наличие не означает 4 года готового контента.

## Расширения M2
Run.actionCounts хранит посещения каждого действия. Condition visits читает конкретный счётчик.
Действия могут иметь wage (base + взвешенные статы, округление после изменения статов)
и seasonal (эффекты текущего сезона). Story-действие не тратит слот: сейчас только вступление.
Save schema 2; parseSave явно преобразует schema 1, восстанавливая только достоверный work.
Имена сохранений/хранилища остаются v1 ради поиска старых файлов; внутренний envelope имеет версию 2.

presentation.ts накладывает белый список текстовых/медиа-замен на каталог. ID/условия/эффекты
не редактируются. UI хранит пользовательские замены отдельно, экспортирует presentation.json.
Для поставки replacements кладутся в content/presentation.json и включаются сборкой.
Новые медиа-слоты уникальны на постановку; общие базовые SVG пока повторно используются как заглушки.
Этот редактор не заменяет будущий редактор событий и графа.

## Расширения M3
Save schema 3. creation хранит распределение очков; rng — состояние генератора; lastAction — рабочую сцену, текст, медиа и итоги. Старые saves мигрируют явно, не по внешнему виду UI. slot сохраняется как счётчик, больше не ограничивает ход: единственный дневной бюджет — energy.
Действия содержат scenes; события могут задавать chance, варианты и choice.media. Сперва проверяются условия/cooldown, затем вероятность. Смена картинки не выполняет повторно эффекты. Seed сохраняется вместе с жизнью.
Команда sleep принимает money/favor/outside, атомарно оплачивает ночь и начинает день. Отдельных автоматических расходов на еду/недельную аренду больше нет. Выносливость — характеристика, energy — расходуемые действия. vitality увеличивает вместимость и восстановление энергии.
Здоровье и стресс — только поля совместимости. Новый контент не должен изменять их или энергию обходными эффектами. UI и тексты используют labels.ts, внутренние ключи сохраняются.
